# 0002. Initial stack and repository layout

- **Status:** Accepted
- **Date:** 2026-11-24

## Context

We need a service that reads LogiSur's daily remitos export and loads the Expreso Andino ones into the carrier's shipments API. We also need a UI to trigger loads and review the results. A Python mock of the carrier API is provided (`expreso-api/`) along with its contract, `API.md`. That folder stands in for a third-party system and must not be modified.

## Decision

- **Monorepo** with separate top-level apps: `backend/`, `frontend/`, `expreso-api/` (vendored mock, read-only) and `docs/`.
- **Backend:** NestJS (latest, v12): ESM, Vitest, oxlint, as generated by `@nestjs/cli`. We removed the scaffold's default telemetry module (`@nestjs/observe`) so the project starts without third-party telemetry.
- **Frontend:** Vite + React + TypeScript (latest `create-vite` `react-ts` template).
- **Local runtime:** Docker Compose runs the three services:
  - **`expreso-api`:** runs on `python:3.12-slim`. The folder is mounted read-only and the server is started through an inline command that binds it to `0.0.0.0`. The script itself only listens on `127.0.0.1`, and we can't edit it.
  - **`backend`:** multi-stage Node 24 image. It gets `EXPRESO_API_URL`, `EXPRESO_API_KEY` and `REMITOS_DIR`. The sample export is mounted read-only at `/data`.
  - **`frontend`:** static build served by nginx. nginx proxies `/api/*` to the backend so the browser stays same-origin, which means no CORS setup.

## Alternatives considered

- **Changing the mock to bind `0.0.0.0` or read a host variable:** rejected, because the mock must stay untouched.
- **Vite dev server in Docker:** deferred. Compose runs production builds; local development uses `npm run dev` / `npm run start:dev` on the host.

## Consequences

- `docker compose up --build` runs the whole system end to end.
- The mock keeps state in memory. Restarting its container resets it, which helps when re-running loads.
- Open decisions for future ADRs: persistence for load runs, how normalization rules are defined, retry and idempotency strategy, and how the export reaches the backend (file mount vs. upload).
